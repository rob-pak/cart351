WEEK 1

Sept 21th

Last week, I read a blog post from Tim Rodenbröker, an educator in the creative coding sphere, titled "Is Creative Coding with AI… still Creative Coding?". This is a topic that immediately piqued my interest as I've always wondered where creative coding fits in a world of AI.

He posted a simple statement online which generated a lot of debate: "Creative Coding with AI is not Creative Coding". His issue seems to come from semantics, as the term "creative coding" seems, more often than not, to be used to describe the process of vibe-coding to create art, thus changing its meaning from what it was before AI. In his view, creative coding should still be done by hand, as that process comes with intention and discovery.

I wanted to highlight a few opinions shared by the community that I found interesting (paraphrased by me):

  • Coding "by hand" doesn't make it creative coding. There is a lot of derivative material that is just copy/paste with little expression. Tools that reduce the barrier to express yourself are of help.
  • "Manual coding" leads to accidental discoveries. The process is never a linear "idea to execution" pipeline that AI prompting seems to encourage. However, for boilerplate and repetitive code, there isn't anything wrong with AI. There's no creative potential in the thousandth time you write code to preload images.
  • Photography freed painting to go abstract, since realistic depiction was no longer painting's job.
  • Creative Prompting (as a suggestion for the term we should use to describe vibe-coding art)
  • Pottery analogy: the vase is not the end goal, but creating it through pottery is. Being able to vibe-code to reach a similar result to creative coding is giving the illusion of entering the same category, forgetting the value and meaning of the process itself.

Personally, AI is a depressing and difficult reality for me to accept. I still write my code manually and I still spend hours scratching my head. I think the struggle is an important part of learning and we should not outsource our thinking if we wish to prevail as a society. But part of me still sees a lot of value in AI in a learning environment when it is used correctly. I feel like a hypocrite!

WEEK 2

Sept 28th

I was surprised to learn that, in Python, functions needed to be defined before they can be called. It does make sense, considering it's an interpreted language and instructions are executed sequentially. I used to think JavaScript was fully interpreted but after some further reading, I found out that it uses Just-In-Time compilation. I knew functions that in JavaScript were "hoisted" but I didn't realize that compilation was involved to achieve that.

WEEK 3

Oct 5th

As I was working on the Web API exercise, I wondered how I could handle access to invalid dictionary keys. At first I was simply doing entry[key], but I learned that this either returns the value or throws an error if the key doesn't exist. After some Googling, I found that there's a get() method that returns a None value if the key is invalid, which was what I was looking for.

I also wonder what the correct approach is for error handling with Web API calls. I imagine try/catches are the way to go. I will explore that next time!

The Rich API was fun to work with. However, I spent a lot of time trying to add a bottom border to my rows and style it. I couldn't figure it out. Anyhow I'm happy with the result.

WEEK 4

Oct 26th

I'm excited to learn more about Flask as I have not done any backend development in ages, apart from the occasional PHP work on WordPress sites. After the first Flask class, I wondered if there was a straightforward way to serve 404 pages using Jinja. Turns out there is! All you have to do is use the @app.errorhandler(404) decorator and provide your 404.html template.

I wonder what kind of creative project I could do using Flask. I've always wanted to try the Web MIDI API so maybe there's some weird music/backend interaction I could come up with.

As I was writing this journal entry, I did some research to see what had already been done in this area and I stumbled upon this really interesting art project. Artist Erika Tan made an "instrument" that reads collection data and triggers sounds. Maybe I could do something similar, where user-submitted data is stored in a database and then translated into sounds on the client-side.

WEEK 5

Nov 2nd

This week, I had to submit an essay for FFAR248. I wrote about the Processing Foundation and its place in the age of AI. It got me thinking because, for a long time, their mission was to promote software literacy in the art world by providing accessible, open source tools. However, with AI, any artist can simply send instructions in plain natural language and have something generated. Isn't that a big leap in accessibility?

I'm aware that it's not that black and white as AI comes with a lot of baggage. The Foundation also has a different definition of accessibility from what I'm implying here, but I still find the question interesting. I wanted to see how the Foundation responded to this new technology, but I didn't find much. Apart from an article discussing AI in an educational context, I couldn't find anything that clearly outlined its position.

However, what I did find interesting, were the subtle changes they made to its website over the years. Using the Wayback Machine, I compared their previous mission statement to their current one. It seems like the Foundation currently places a greater emphasis on community and activism, by advocating for equity, collaboration and open source software "free of corporate gatekeeping". I wonder if this shift is some kind of response to the changing technological landscape. Maybe I'm reading too much into it.

WEEK 6

Nov 9nd

I'm currently studying Python in my COMP348 class and I'm starting to have mixed feelings about the language. I had an assignment that ended up being around 200-300 lines of code and I started having a hard time reviewing it. I find that the lack of explicit block endings hurts readability. All the whitespace gets confusing and the code starts looking chaotic surprisingly quickly. I can't imagine what it would look like in an application with thousand lines of code.

I didn't expect to feel this way as Python is generally considered to be very readable and easy to learn. I do find it very easy to write in. Coding that assignment felt very natural with little friction. Well, apart from figuring out where my indention should go in my few nested if statements and loops. Maybe it's just a matter of getting used to it.
